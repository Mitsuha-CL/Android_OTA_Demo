# Android 应用 OTA 系统设计文档（守护进程方案）

## 一、项目概述

本项目旨在实现一个运行于定制 Android 设备上的应用 OTA 系统，具备以下能力：

- 强制更新（不可跳过）
- 静默安装（无需用户操作）
- 高可靠（断点续传 / 重试 / 崩溃恢复）
- 可扩展（支持灰度发布、回滚等）

---

## 二、系统架构概述

系统采用多进程架构：

- 主进程：负责 UI 与用户交互
- 守护进程：负责 OTA 核心逻辑执行

模块分层如下：

- 表现层（UI）
- 业务层（UpdateClient）
- 通信层（AIDL）
- 服务层（UpdateService）
- 功能模块（下载 / 校验 / 安装）
- 系统能力层（PackageInstaller）

---

## 三、模块需求说明

---

### 3.1 UpdateClient（主进程）

#### 职责
- 绑定 UpdateService
- 发起更新请求
- 接收更新状态
- 通知 UI 层

#### 输入
- 用户点击更新
- 应用启动事件

#### 输出
- 调用 AIDL 接口：
  - checkUpdate()
  - startUpdate()

#### 约束
- 不参与实际更新流程
- 不直接操作安装逻辑

#### 异常处理
- Service 未连接 → 自动重连
- Binder 断开 → 重试绑定

---

### 3.2 UpdateService（守护进程）

#### 职责
- OTA 全流程执行
- 状态机管理
- 提供 AIDL 服务接口

#### 输入
- checkUpdate
- startUpdate

#### 输出
- 更新状态回调
- 安装结果

#### 状态机
- IDLE
- CHECKING
- DOWNLOADING
- VERIFYING
- INSTALLING
- SUCCESS
- FAILED

#### 约束
- 必须运行在独立进程
- 必须为前台服务

#### 异常处理
- 任意阶段失败进入 FAILED 状态
- 通知 WatchDog 处理

---

### 3.3 UpdateController（流程调度）

#### 职责
- 控制 OTA 执行流程
- 管理状态流转

#### 输入
- 版本信息
- 下载结果
- 安装结果

#### 输出
- 调用下载 / 校验 / 安装模块

#### 核心方法
- checkUpdate()
- startUpdate()
- onDownloadComplete()
- onInstallResult()

#### 约束
- 流程必须串行执行
- 不允许重复更新

---

### 3.4 VersionChecker

#### 职责
- 请求服务器版本信息
- 解析更新策略

#### 输入
- 当前版本号
- 设备标识

#### 输出
- 版本信息 JSON

#### 约束
- 使用 HTTPS
- 支持重试机制

#### 异常处理
- 网络失败 → 重试
- 数据异常 → 终止更新

---

### 3.5 DownloadManager

#### 职责
- 下载 APK 文件
- 提供进度
- 支持断点续传

#### 输入
- 下载 URL

#### 输出
- 本地 APK 路径

#### 约束
- 文件必须完整
- 不重复下载同版本

#### 异常处理
- 网络中断 → 自动恢复
- 下载失败 → 重试

---

### 3.6 VerifyManager

#### 职责
- 校验 APK 文件完整性

#### 输入
- APK 文件
- 校验值（MD5 / SHA256）

#### 输出
- 校验结果（true / false）

#### 约束
- 校验失败必须终止安装

#### 异常处理
- 校验失败 → 删除文件并重新下载

---

### 3.7 Installer

#### 职责
- 执行静默安装

#### 输入
- APK 文件路径

#### 输出
- 安装结果

#### 核心流程
- 创建 Session
- 写入 APK
- 提交安装

#### 约束
- 必须为 system app
- 必须签名一致

#### 异常处理
- 安装失败 → 返回错误码

---

### 3.8 WatchDog

#### 职责
- 失败重试
- 崩溃恢复
- 进程保活

#### 输入
- 异常事件
- 失败状态

#### 输出
- 重试策略执行

#### 策略
- 最大重试次数：3
- 指数退避

---

## 四、安全设计

- HTTPS 传输
- APK 校验
- 防降级（versionCode 递增）
- 强制更新控制

---

## 五、总结

系统通过“主进程 + 守护进程 + 系统权限”的架构，实现稳定可靠的 OTA 更新能力。
